当前构建与运行（唯一现行入口）
原生运行图片和音频已经迁入 Git LFS。只取得源码或 LFS 指针文件不能构建可运行的 App；下文历史章节描述的是各版本当时的分发方式，不替代此处的现行步骤。
在安装 Git LFS 后，从仓库根目录执行：
git lfs install
git lfs pull --include="native/ios/CatLife/**"
python3 -B native/ios/scripts/check_runtime_assets.py

检查通过后，用 Xcode 打开 native/ios/CatLife.xcodeproj，选择 CatLife scheme 和 iPhone 模拟器，点击 Run；也可以继续执行：
先确认外置硬盘已挂载；编译缓存统一使用 AGENTS.md 指定的外盘目录，不回退到本机。
CATLIFE_CACHE='/Volumes/AI作品素材/开发缓存/本机编译缓存/cat-life/manual-simulator'
xcodebuild -project native/ios/CatLife.xcodeproj -scheme CatLife -derivedDataPath "$CATLIFE_CACHE" CLANG_MODULE_CACHE_PATH="$CATLIFE_CACHE/ModuleCache.noindex" SWIFT_MODULE_CACHE_PATH="$CATLIFE_CACHE/ModuleCache.noindex" -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build

已生成工程的第一个构建阶段也会检查运行素材。发现 LFS 指针、缺失文件、空文件或错误的 PNG/JPEG/CAF 文件头时，会报出具体路径和下载命令并停止；构建过程不自动联网或修改素材。scripts/runtime_assets.json 是必须随资源变更更新的运行文件清单，可检测整套 imageset 被删除的情况；该检查不替代图片解码和实际音频验收。
工程已包含本地 CatGameCore Swift 包，无需第三方运行代码依赖；运行素材仍需按上述步骤下载。模拟器构建不需要 Apple 开发者账号；安装到自己的 iPhone 时，需要在 Signing & Capabilities 选择自己的 Team。网页版仍直接打开根目录 index.html，不依赖原生资源。

仅测试 Foundation 核心逻辑，不需要运行素材：
cd native/ios/CatGameCore && swift test

工程和资源维护（以下命令同样从仓库根目录执行）
通常直接使用已提交工程，不需要重新生成。新增 Swift 源文件后，可用 ruby native/ios/scripts/generate_project.rb 生成工程（需要 xcodeproj gem）；生成器在创建或替换工程前先执行同一素材检查，失败不覆盖原工程。
新增美术资源前先按文末说明下载 ArtSource，再用 python3 native/ios/scripts/import_assets.py 更新资产目录；场景原图直接复制，AppIcon 由 macOS sips 导出为 1024×1024，原始设计图保留。确定添加或移除运行素材后，执行 python3 -B native/ios/scripts/check_runtime_assets.py --update-manifest，这会同时更新 runtime_assets.json 与 runtime_assets.xcfilelist，把两个清单与素材一起提交；普通构建和生成工程不会自动重写清单。
前置检查的临时夹具自测：python3 -B -m unittest discover -s native/ios/scripts -p test_check_runtime_assets.py。自测不改真实素材，不运行 Xcode 或模拟器。

当前范围
- 奶油玩具屋房间首页，真实金币/体力/猫粮状态。
- 喂食、清洁、陪玩；用品不足可进入原生商店购买猫粮、猫砂、逗猫棒。
- 底部“背包”可查看猫粮、猫砂数量和玩具剩余使用次数，直接使用或补货；消耗沿用同一存档，保存成功才关闭背包并播放互动。
- 五种职业按等级解锁：发传单、便利店兼职、宠物店助理、IT 工程师、猫咖管理员；工作结束获得固定基础金币和经验，离线按真实时间结算一次。
- 等级与经验持久保存，每次升级需要当前等级 × 100 经验，超出部分保留；工作页显示等级进度、职业选择和最近一次结算。结算页展示的奖励已到账，反复查看不会再领取。
- 玩家档案首页以紧凑身份卡展示人物、名字、状态与等级，点击人物弹出等级经验、体力、心情、金币及累计打工次数；穿戴和加成为独立二级页。六种形象可自由切换，性别和外观不改变能力。
- 四件基础穿戴道具免费赠送到衣橱，初始不自动穿戴；帽子、上衣、鞋子、挂饰各占一个槽位，提供心情与体力成本减免或时长缩短。预览与新工作使用同一核心报价，途中换装从下一次开工生效。
- 玩家可开始睡眠和主动醒来；睡眠期间每真实小时恢复 20 体力和 20 心情，不叠加普通的每小时 5 体力恢复。睡眠与工作互斥，仍可浏览页面和照顾猫咪，后台与重启后继续结算。

- 壁画只能摆在墙面，其余家具和食盆摆在地板。“完成”一次提交整套布局，“取消”还原本次布置中的移动、收回与摆放。
- 点击猫窝或爪印坐垫，猫会走到入口、前爪搭边、撑起身体并让后腿跟上，再趴下休息；醒来伸展后分步下垫；轻点休息中的猫可唤醒。空闲时也会偶尔自己去休息。
- 猫在家具上躺稳后开始按真实时间恢复精力：猫窝 12 秒、坐垫 9 秒，一次最多恢复 20 + floor(舒适度 / 20)，精力上限仍为 100。提前离开只结算已休息部分；本次不增加猫咪心情、健康或亲密度。
- 原生猫档案，暂未迁移社区 NPC、医院、繁殖、银行或游戏厅。
- 独立 JSON 本地存档、上一份备份及失败提示；完整网页旧档导入尚未实现。

核心逻辑在 CatGameCore 包；SwiftUI 层将动作和恢复流程串行提交并保存，保存成功才播放场景反馈。
清洁、陪玩和基础喂食遵循网页的物品消耗及数值规则；五种职业沿用网页的基础数值，第 19 版再按已穿戴道具计算新工作的实际时长和成本。暂不含随机工作事件、玩家饥饿及心情对时长的修正，心情扣除后最低为 0。
房间渲染使用独立美术资源，文字与按钮均为原生控件。
场景由 UIViewRepresentable 中的 SKView 显式呈现；退到后台暂停渲染，回到前台按时间戳恢复进度。
布置草稿包含食盆和全部家具，允许与自动存档并行；只有点击完成提交整套布局时暂时锁定拖动。收回家具只移除摆放记录，不删除拥有的物品；背包的“家具”分类可将已收回物品重新摆入房间。
家具所有权保存为 inventory.furniture，摆放记录保存为 home.furniture；食盆继续沿用 home.bowlPosition。原生 schema 1 存档缺少家具字段时补入默认家具，显式保存的空数组 [] 会保留，不会在重启时重新填满房间。网页 localStorage 和已有猫咪、用品、工作进度不受这项兼容处理影响。

设计与美术
视觉依据为 docs/ios-room-home/room-home-refined-v2.png；根据走动穿过食盆的反馈，构建号 4 将猫等比例缩至原先约 2/3，所有姿态和影子沿用统一尺度。
ArtSource 中保存内置 image_gen 生成的独立 PNG 与各自提示词；Assets.xcassets 为运行时资源。
第 20 版人物素材按用户提供的 IMG_1160.jpg 逐人提取为透明立绘，保留对应脸部、发型、配色、衣服及姿态；原图、提示词与来源说明见 ArtSource/player-build20/README.txt，旧第 19 版源图保留。
构建号 9 使用 ArtSource/Furniture/room-empty.png 作为空房间底图，保留原镜头、建筑轮廓、窗户、墙脚、木地板和台阶；原 room-background.png 保留。家具拆成 8 种独立透明 PNG，其中植物素材对应大小两盆独立实例，共 9 件家具。完整提示词见 ArtSource/Furniture/prompts.json，生成路径与图像注册数据见同目录 generation-manifest.json 和 registration.json。全部素材通过内置 image_gen.imagegen 逐件生成并原样复制到对应 imageset，未用脚本绘制、抠图或修改像素。
猫咪动作使用 expressions、walk、rise、meal、play、rest、step 七组透明图集，每组 8 帧，共 56 个姿态，源图与提示词保存在 ArtSource/Animation。rest 在构建号 10 新增趴卧、闭眼、醒来和伸展；构建号 11 的 step 补上抬前爪、撑身、后腿上垫和分步下垫。内置 image_gen 生成的原图分别保留为 cat-rest.png、cat-step.png，提示词与注册记录保存在同目录。原来的两张猫图仅保留为图集不可用时的回退资源。
CatActor 在加载图集时按透明像素边界和低位脚掌位置注册各帧，用 SpriteKit UV 取帧，不改写源图；保持脚底基线，减轻切换姿态时的位置和尺度跳动。走路和扑跳以整组稳定的身体中心对齐，避免伸出的爪子拉动整只猫。所有图集在首次交互前缓存。
走路先起身，再根据实际移动距离推进迈步相位，起步和停步有缓动；待机采用不等间隔的眨眼、偶尔双眨、侧看、转耳和满足表情，胸肩呼吸幅度很小、呼气略长，空闲时偶尔在前景地板上短距离散步。
上垫使用独立 step 图集：从安全入口斜向靠近，前爪接触、短暂停顿撑身、后腿跟上，站稳后再趴下；下垫按前爪先落地、后腿跟随的顺序进行。坐垫的支持高度按猫宽的 0.14 校准；猫窝按黄色床垫前沿的实际位置解出抬升高度，同时降低地面投影，最终睡姿位置保持不变。猫窝前沿只在全身进入后的 supported 阶段遮挡低处，攀爬和下垫时不覆盖胸腹。攀爬中喂食或进入布置会从当前姿态、位置和高度安全撤回地板，再继续后续操作。
进食先走到安全转身点，再固定朝向靠近食盆，低头咀嚼、短暂停顿与偶尔舔嘴；吃完倒退离开食盆，才转身沿原路返回坐下。陪玩先看向玩具、蓄力，再做一次低幅小扑和落地缓冲；清洁反馈是短暂闭眼与轻微抖动。
地面导航与碰撞
RoomFloor 将空房间底图中的真实地板多边形按相同 aspect-fill 变换映射到场景，并裁掉画面外区域；墙面、窗台和平台前缘不属于行走范围。地板家具不再烘焙在背景或固定地板缺口中，而是根据当前摆放位置形成动态障碍；移动、收回或重新摆放后更新占位，收回后露出的地板可重新参与寻路。壁画使用墙面摆放范围，不占据地面。
RoomNavigation 同时检查整只猫的地面占位和整段扫掠路径；食盆及当前地板家具的实体按猫的宽深膨胀后成为障碍，寻路与路线简化都不能穿过它们。靠盆进食和陪玩同样使用当前家具障碍。没有合法路线时保持原地，不能用直线兜底。
CatActor 只执行已验证折线路径，步态按总里程连续推进，不在每个转角重新起停，也不用会切入障碍的圆滑曲线。喂食以图集嘴部与猫粮的实际像素位置对齐；靠盆段使用有方向偏移的脚掌矩形，持续检查盆体和墙面，普通行走仍使用完整占位；扑跳按伸展后更大的占位检查起点、落点与中间整段。
拖动家具或食盆要遵守各自墙面/地板区域及占位限制，地板摆放不能压住猫或封死全部进食侧；每次接受位置都更新导航障碍，触摸取消恢复当前草稿位置。布置中的物品移动与收纳均属于同一草稿，取消整次布置时恢复进入布置前的布局。旧存档的不合法食盆位置只投影到最近可用地板位置，不自动重写存档。
猫与食盆按地面锚点排序：猫在盆前会显示在前面，走到后面才被遮挡。低头进食时独立绘制食盆前缘：嘴部可越过后沿接触猫粮，脚掌仍被盆体遮挡。测试时还独立用当前精灵位置检查碰撞，避免缓存旧障碍造成漏报。

连点时合并的是尚未播放的视觉反馈，当前动作不会被硬重置到房间原点；每次成功的喂食、清洁或陪玩仍由原有 Store 独立处理消耗与保存。动画帧与临时姿态不写入存档；第 17 版新增的休息会话单独保存实际起止时间，由核心按时间结算，不按播放帧数发放精力。
开启系统“减少动态效果”后，停止自主散步、循环呼吸和跳动；原有照顾互动改为短暂的平静表情。主动点击猫窝或坐垫仍保留安全进出所需的路径移动，省去呼吸和步态形变。进入布置会结束一般视觉反馈并停在当前位置；若猫正在家具上，先等待它走回安全地板，再开放拖动和收回。切到后台由 SKView 暂停场景，回到前台继续显示，游戏进度仍按真实时间同步。
app-icon-v2.png 为正式图标源图：薄荷绿背景、小橘笑脸与薄荷领结；原始提示词同目录保存。

构建号 17 休息恢复（0.2.0，2026-11-01）
玩家睡眠持续至主动醒来，按真实经过时间每 180 秒恢复 1 体力和 1 心情；不足 1 点的时间余量分别保存，跨同步、醒来再睡及重启保留，数值达到 100 时不积攒额外奖励。睡眠期间不叠加普通的每小时 5 体力恢复，工作与睡眠不能同时开始，浏览页面和照顾猫咪仍可进行。后台与冷启动继续结算玩家睡眠，重复开始、重复醒来或时间回拨不会重复领取恢复。
猫咪实际走到猫窝或坐垫并躺稳后才开始休息会话。猫窝为 12 秒、坐垫为 9 秒，完整一次的精力额度为 20 + floor(舒适度 / 20)，按已休息比例向下取整逐步结算，精力不超过 100。提前唤醒或成功照顾猫咪只结算已经过的部分；照顾失败不取消休息。布局实际改变时安全结束已有休息。本版只恢复猫咪精力，没有额外心情、健康或亲密度奖励。
休息区间暂停该猫的精力衰减，休息前不足一次衰减的时间余量保留，其它状态继续正常衰减。后台或离线最多结算这一次休息的额度，到期后的时间恢复正常精力衰减；到期会清除会话。冷启动先同步真实进度，再结束尚未到期的猫咪休息，让新场景从地面开始，不伪造已到达家具的姿态，也不重复奖励；玩家睡眠则保持。
