# PR #3 修订核对（0.5.2 / 25）

本次保留并整合欢迎页 0.4.3、音频 0.5.0、角色改名 0.5.1，以及此前的原生功能。0.5.2 为修订 PR 的候选版本；手机最近交付版本仍为 0.5.1（24），本次没有覆盖安装或改动真实存档。

| 审查项 | 修订方式 |
| --- | --- |
| P2：持续写盘失败锁住界面 | `isBusy` 仅覆盖实际读写；自动写入最多尝试三次并退避，错误提示每次故障只出现一次。保留休息退出原时刻，手动操作或“重试保存”可以恢复。 |
| P2：成功读档被回写失败误判 | 独立处理读和写；读成功后保留已持久化的快照，失败结算不显示已到账。加载过程中持有忙锁，防止前后台事件并发提交。 |
| P2：喂食和玩耍同步寻路 | 后台只接受不可变几何快照；回到主线程前验证版本和展示状态。取消旧计划，前台恢复已扣物品的待执行动作。 |
| P2：大资源与 QA 淹没源码 | 原图、运行图片/音频、QA 媒体、日志及大型 JSON 使用 LFS；小型摘要与源码留在普通 Git。默认仅取运行素材；完整原件保留，可按需拉取。修订提交直接基于 PR 基线构建，不把旧的普通二进制提交作为祖先。 |
| P2：超大文件与生产测试逻辑 | 按职责抽出图集、路线、房间绘制、规划和诊断；UI 用例按功能拆分。场景/音频诊断、测试种子、故障注入和特殊启动参数限定 `#if DEBUG`；Release 目标不构建测试包。 |
| P3：金币封顶阻止时间推进 | 工资按剩余容量封顶，结算记录写实际到账，经验和次数继续推进，重复同步不再发奖；极端经验溢出使用明确 `work.progressLimit`。 |
| P3：子串猜测错误文案 | 改为完整错误键的明确映射，未知错误使用通用提示。 |
| P3：动作同步约定不一致 | 所有引擎变更动作先同步；失败动作保留时间结算，但不产生动作消费。 |
| P3：频繁写盘及备份过近 | 普通自动检查延长至 60 秒，仅元时间戳变化跳过写入；休息事件、到期工作、用户动作及时保存。有效备份最多每 5 分钟轮换，跨启动保留间隔。 |
| P3：无用常量 | 删除旧工作时长、工资和睡眠恢复常量。 |
| P3：损坏证据无限累积 | 相同内容复用，恢复成功后保留最近三份；清理失败不误报已成功的恢复。 |
| P3：网页部署包含 native | `.vercelignore` 排除 `native/`、设计资料和 Git 元数据。 |
| P3：IDE/构建文件误提交 | `.gitignore` 排除嵌套 `xcuserdata`、`DerivedData`、`.build`、结果束和归档。 |

最终构建、UI 回归、Git/LFS 及提交统计见同目录 `verification.json`（收尾时写入）。核心与 App 单元测试摘要、隐私复核均独立留证。历史完整原始记录保留在 LFS；本轮不再归档大段构建日志或完整结果束。

验证边界：不是全部历史 UI 用例重跑；不等同玩家真机验收。已有模拟器音频会话性能警告仍需物理设备及长时性能分析，不能凭无卡死报告宣称已解决。
