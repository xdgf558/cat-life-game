# 0.13.3（49）存档原件保护与安全重试

发布补充：PR #14 已合并（b3658c4），2026-11-06 07:01（GMT+8）上传成功；App Store Connect 已显示 0.13.3（49）正在处理。未关联测试组、邀请或提交 Beta Review，未安装真实设备。以下为合并前的实际验证记录，同源码未重复运行测试。

## 本轮修复

- 加载失败后的恢复先重新读取主档和自动备份。主档已可读取，或主档缺失但自动备份可读取时，返回明确的“重试读取”结果；此分支不保全、不清理、不覆盖任何文件。普通加载失败页重试为主按钮，较新版本仍按用户选择优先打开 TestFlight。
- 较新版本原件移入独立 `newer-save-<UUID>.json` 名称空间，不参与普通损坏证据的三份清理，相同字节去重。旧 `unreadable-save-*` 中的较新原件以及更新后已可读取的原件会先升格保护；升格失败不会阻止读取完好的主档，也不会清理旧证据。
- 存档管理列出原件的格式版本、另存时间、实际大小，并可通过系统“文件”导出。导出使用既有格式 1 封装，snapshot JSON 原字节嵌入，不重新编码未知字段或大整数；支持该格式的版本可通过普通备份入口手动导入。更新本身不会自动恢复。
- 普通备份与原件共用唯一系统导出面板，分别保留准备文档和结果提示。文件名包含原件时间与标识片段；导出原件无需先写当前进度。普通备份仍沿用原先的保存规则。
- 普通损坏文件最多保留三份诊断副本，文案明确其不可保证恢复。路径穿越、符号链接、非普通文件、非法 JSON/日期与 5 MB 限制保持校验。

保留 schema 6、备份格式 1、5 MB 限制、单槽导入前恢复点、现有 UI/图标和网页版隔离。候选玩家更新历史为 49/44/43，45–48 未单独发布。

## 验证

313 项 Core、135 项 App 测试通过。新增 10 项 Core 测试和 2 项 Store 回归，覆盖可读主档无变更拒绝、缺主档但可读备份、原件跨多次清理保留及去重、历史迁移、兼容原件导入、未来字段精度、文件边界和真实写入失败。原件导出也在当前存盘失败时验证成功，不把普通备份磁盘失败导出的问题标为已修。

5 个不同 UI 方法、6 次目标执行通过：SE 的加载失败重试/取消、存档页三语、49/44/43 版本历史；SE 与 Pro 的真实文件导出原件再选择、版本拦截和进度不变；SE 的普通文件面板取消。结果标签为 `se-welcome`、`se-settings`、`pro-preserved-final`、`se-preserved-final`。原件实际文件流程耗时 Pro 142.106 秒、SE 149.198 秒；未只以按钮存在作为导出成功。已查看两种屏幕的原件列表、系统面板与版本错误卡。

125 个运行资源、868 个三语文案键及占位符检查通过。最终 Debug 构建、签名 Release 归档、版本/Bundle ID、dSYM、隐私清单、加密声明及 Release 不含测试入口检查通过。最终候选为 `Distribution/CatLife-0.13.3-49-release-final.xcarchive`，二进制 SHA256：`b7c5bf9e8e7ef5f4af435305901905612c6bd11d6ca95f2606ba581d26821105`。同版 `release` 为导出面板修正前候选，不用于发布。

## 已知边界
