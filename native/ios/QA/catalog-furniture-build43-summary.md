# 0.12.0 (43) cat collection and furniture placement

Prepared for PR review; not installed or uploaded to TestFlight. This feature branch builds on the separate 0.11.2 task/health repair checkpoint. The web game is unchanged.

The cat collection has all/adopted/unadopted filters, four cards per page and a breed count that does not count duplicate appearances twice. Bluebell (蓝影 / 藍影) is available for 600 coins at player level 4 and room level 3; adopting the cow cat first is not required. Adoption and the charge remain one save transaction. Names, needs, health and companion selection stay independent per cat. Ten generated blue-cat assets include seven eight-frame animation sheets, with separate paw and mouth registration. Existing orange/cow art and room/cat dimensions are unchanged; provenance is in `../ArtSource/blue-cat-build43/`.

Floor furniture can be horizontally mirrored in the arrangement tray. Direction and position share the existing draft/save transaction; cancel restores the original, failed saves retain the draft, and storage/replacement/relaunch preserve direction. Wall art and the bowl do not expose the control. Sprite/front-layer orientation and the preferred rest-entry facing follow the stored direction.

Two independent issues affected cat-bed placement. The drag preview used the full rectangular corners against the diagonal window wall; only the bed's floor containment now uses a conservative octagon enclosing the same-bounds ellipse. It keeps all four axis extremes, concave-wall/swept checks and full rectangular collisions with other objects. Cat walking, bowl and other furniture rules are unchanged. Separately, full-height portrait scenes could require a climb above the existing 0.55-cat-width limit, so release validation rejected every bed position. Those beds now approach farther before forepaw support, with elevation 0.54 cat widths and contact progress capped at 0.40. Safe old climbs keep progress 0.14, and the final visible sleeping point is unchanged. The independent yellow-rim/pixel-paw audit retains its original error limits.

The original starter cushion could also lie outside a tall viewport. New rooms place it at (0.22, 0.70). Schema 6 migrates only a complete unchanged legacy starter layout **including the default bowl position**; custom layouts, moved bowls, stored items, extra placed items and current-schema saves are not moved or refilled. Existing cats, custom names, rewards, inventory, room level and orientation remain intact. Older clients reject schema 6 before decoding unfamiliar appearances rather than damaging the save.

Validation completed:

- 286 Core tests in 27 suites, including migration, atomic adoption/orientation, targeted task/health rules, diagonal and concave floor boundaries, thin obstacles and deferred navigation.
- 103 App tests, including cold asset loading for all three appearances, independent adoption/name/health state, failed-save retry, full-height bed/cushion geometry and furniture drafts.
- Simulator build-for-testing and signed Release archive; 121 hydrated runtime resources, matching 834-key locale tables, diff whitespace checks. Signature, matching dSYM, privacy manifest and absence of UI-fixture flags checked.

Eleven distinct targeted UI methods passed on their latest executions across small and large simulators. They cover three-language locked offers, adoption/rename/companion persistence, nine-cat paging, town/bag navigation, latest-three releases, real meals/pounces, blue and cow bed/cushion entry and exit, turning/storing/replacing furniture, and interrupted bed climbs. The final small run passed 2/2 and large run 4/4. The window-floor case uses a real pinch to show the whole room and a target at source artwork (255, 750): it proves the old rectangle would reject the point, checks the conservative footprint stays on the floor, and requires move-event samples to reach within two world points of the target before release. It also checks the camera did not pan, cancellation survives cold launch, and a saved mirrored layout survives reopening. Final images were visually inspected for support and wall clearance.

Raw logs, screenshots, recordings and xcresults remain outside Git in the external build cache.

Verification iterations retained externally: the first large-screen blue-cat test reproduced the bed-height rejection; after that repair, it exposed the starter cushion clipping. Both production causes were fixed. A new test initially treated the scene's `savedFurniture` diagnostic as durable disk state, although it contains the current arrangement draft; it now checks actual draft coordinates and proves cancellation through a cold restart. Cross-review additionally required the bowl to remain at its default position before migrating a legacy starter layout; a moved-bowl preservation case was added and the full Core suite rerun. The migration test initially used a home name longer than its 12-character limit; the fixture was corrected and full-state equality was retained. No collision, paw-contact, resource-charge or saved-state assertion was weakened to pass a failure.

Not performed: physical-device acceptance, the entire historical UI suite, iPad or extreme accessibility text-size/VoiceOver testing, and real-device cold-start profiling. This remains the existing local, single-companion game; social visits, breeding, cloud saves and other unrelated web features were not added. TestFlight upload must wait for user PR approval.
