# 0.13.2（48）存档管理与恢复 UI/UX

状态：开发和本轮验证已完成，PR #14 待复审；未合并、未上传 TestFlight、未安装真实设备。

## 范围与设计适配

依据用户交付的 `design_handoff_catlife_0.13.zip`，重做设置存档分组、当前进度、备份明信片、导入对照与确认、恢复点、错误/成功卡，以及欢迎页失败和恢复完成状态。较新版本存档优先提供 TestFlight 更新入口，无法打开时给出手动说明。

- 等级、金币、猫数、房间、玩家名及时间来自现有快照；文件名与大小来自真实协调读取结果。对照表显示数值升降、较早进度提示，并通过明确勾选确认替换。
- 处理中禁用返回、关闭和底栏切换。步骤只解释实际操作，不伪造逐步完成进度；现有引擎先计算候选离线状态，再保全恢复资料并写入，界面不改变此顺序。
- 成功后显示实际进度和实际恢复点；启动恢复仍停留欢迎页，由玩家手动进入。相同备份可能由引擎去重，成功文案不承诺每次都生成新恢复点。
- 本轮未改 Core、GameStore 持久化、schema 6、原生封装格式 1、5 MB 上限或网页版。设计中的重置行没有对应原生功能，本轮不新增删除存档能力；现有一个恢复点及上一轮两项 P2 修复继续保留。

## 迭代与边界

首轮发现固定标题的父级无障碍标识覆盖返回按钮，已将标题与滚动区拆为兄弟视图；木牌自身改为单一本地化标签。视觉核对发现成功页位置偏上、错误页所用 SF Symbol 空白，已改为居中卡与有效图标。极大字号初次操作通过后，截图仍显示固定邮票图标溢出及四列对照拥挤，因此改用固定装饰图形、全宽文件名和纵向对照。移除无人调用的对照表父标识，避免覆盖每行独立标签和值。

首次测试构建暴露展示工具调用主线程文案的隔离要求，已明确 MainActor。旧版本号/导航栏测试期望、Files 本地位置中英文空格差异及极大字体所需滚动次数已同步修正；其中一次并行编译早于测试辅助修改完成，后续冻结输入并重建复测。保留历史失败日志，不把操作测试通过代替视觉核对。

真实设备 TestFlight 跳转、iCloud/第三方文件提供方下载与中断、跨设备分享、VoiceOver 朗读仍待验收。未修改真实玩家存档。不可用恢复点丢弃、未来时间检查、磁盘故障时内存导出、日期文件名/专用类型和备份签名仍是后续范围。
